# TCP connectivity milestone report

Implemented and validated on the real Windows host. Final repository gate and refreshed local TCP acceptance completed 8 November 2026. Raw artifacts preserve their own timestamps. No infrastructure-control capability was added.

1. **Architecture.** `backend/app/services/tcp.py` performs bounded asynchronous TCP establishment and immediate socket closure. Application code records and interprets the result. Connection latency and total resolution/connect latency are separate fields. Windows IPv6 uses a complete numeric sockaddr.
2. **Target selection.** Existing monitor/health URLs, inventory URLs and explicit inventory ports are reused. HTTP/HTTPS defaults are 80/443. Additional ports use the service hostname/IP, with monitor hostname fallback. Deduplication and hostname normalization prevent duplicate targets. A separate CLI command accepts exactly one deliberate host/port.
3. **Safety and bounds.** Three-second overall endpoint deadline, four TCP slots per process, existing bounded DNS workers, at most 32 DNS results, validation of every returned address, one pinned numeric address and no re-resolution. Batches cap at 50 endpoints. Concurrent same-service probes are refused; per-service/target cooldown is five seconds. No payload, authentication, scanning, banner collection, shell, service control or network/firewall modification exists.
4. **States.** Reachable, refused, timeout, resolution-failed, blocked/unreachable, invalid and unknown. Failure categories distinguish DNS, safety-policy denial, local access denial, unreachable network/host, timeout, refusal, busy and other connection errors. No inferred crash or firewall explanation is reported.
5. **Evidence.** Distinct `tcp_observation` records carry service, hostname, pinned address, port, deterministic outcome, latency, exact UTC timestamp, failure category and observation ID. Live responses use C labels and retain traceable source records. No LLM decides connectivity.
6. **CLI.** `grimoire services tcp [service]` checks configured targets; `grimoire network tcp HOST PORT` checks one deliberate target. Both support `--json` and human-readable output. Direct single-target CLI results are transient and do not create inventory/history.
7. **API.** POST/GET `/api/services/{id}/tcp` trigger/read observations. POST accepts omitted/empty input and rejects target override fields. GET includes configured targets, latest records for current targets and retained history. Services `health=true` attaches the same summary. No arbitrary target network API was introduced.
8. **UI.** Services cards include Inspect TCP, port/state, pinned address, connection latency, elapsed age, exact timestamp, stale indication and up to five recent samples per target. Syntax and frontend rendering tests pass; a browser screenshot review was not part of acceptance.
9. **History.** SQLite retains 50 TCP samples per service and 5,000 globally. Cooldown returns the original ID/time. Removed/changed targets do not masquerade as newly configured targets. Service deletion cleans TCP observations. Manual samples produce no uptime percentage.
10. **DNS/TCP/TLS/HTTP.** Independent observations retain their own IDs and times. Layer summaries compare matching hostname/port targets. Reachable TCP with HTTP 500 identifies the separate application server error; reachable TCP with a TLS mismatch identifies TLS as an observed failing layer. DNS selection, observation times and addresses can differ. Missing stages stay unavailable; causation is not inferred.
11. **Windows service/events.** Only explicit `local_windows_service` mappings support service-state links. A fresh request can read that exact service; retained snapshots show original evidence IDs/timestamps and uncertainty about current state. TCP joins existing event/incident correlations. Change questions can show at most 20 nearby local System events in a +/- five-minute window around the first selected TCP sample, without claiming the endpoint is local or the events caused its failure. Raw nearby events stay out of optional transport model interpretation.
12. **Real local acceptance.** `scripts/tcp_acceptance.py` passed on Windows with disposable listeners: reachable literal IPv4, localhost hostname, reachable IPv6 loopback, refused closed listener, real connection timeout from a saturated disposable local backlog, configured HTTP/TCP success, cooldown identity preservation, bounded history and API/CLI integration. Only loopback endpoints were contacted. See [local observations](tcp-evidence/local.json) and [run log](tcp-evidence/local-run.txt).
13. **Tests and gate.** Added 35 backend TCP cases and one frontend case. Final repository gate: **577 backend tests passed; 14 frontend tests passed**. Existing HTTP, DNS, TLS, Windows Event/host, log/incident, API, CLI, storage and reliability regression tests passed. Lint, formatting, tracked-file audit and diff whitespace checks passed. One existing Starlette/httpx TestClient deprecation warning remains. Two existing host-acceptance dictionary constructions were mechanically simplified to satisfy the current lint gate. See [gate log](tcp-evidence/check-run.txt).
14. **Real-model reliability.** Both existing suites ran with local Qwen 2.5 1.5B and MiniLM. Development: retrieval hit@5 10/10; grounded QA 10/10; oracle QA 10/10; unsupported/oracle unsupported 4/4 each; logs/extraction/incidents 6/6 each. Held-out: retrieval hit@5 22/22; grounded/oracle QA 22/22 each; unsupported/oracle unsupported 5/5 each; logs/extraction/incidents 7/7 each. All required assertions passed. These are existing exposed suites, not a new unseen assessment. See [summary](tcp-evidence/reliability-summary.json) and [full results](tcp-evidence/reliability.json).
15. **Limits.** One address is checked; no address failover, discovery, scheduling or uptime inference. Concurrency/reservations are per application process. Direct CLI checks are transient. Windows event context is a bounded local sample, and mapped host snapshots may be stale. Tests use disposable local endpoints and deterministic fixtures; no unrelated LAN or public endpoint was probed. Linux/Docker acceptance remains outside this Windows milestone. Monitored-service failures do not affect Grimoire readiness.
16. **Recommended next milestone.** A unified read-only incident timeline that groups existing DNS/TCP/TLS/HTTP, explicitly mapped host/service and event evidence with clear freshness and host scope. Preserve deterministic observations and require explicit mappings; add no infrastructure controls.
